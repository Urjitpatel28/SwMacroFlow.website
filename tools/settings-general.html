Settings — General (Theme & SOLIDWORKS)

Where this lives — the gear in the header

  • Four tabs: General and Scheduled Task save as you go, Copilot has a Save button, About is the version and the licence.
  • Esc, the ✕, or a click outside closes it. Nothing here needs SOLIDWORKS to be connected.

Theme

  • Sun or moon — the lit one is the theme you are in, not the one you would switch to.
  • Applied and remembered the moment you click it, for every session after this one.
  • Until you pick, it follows whatever Windows itself is set to.

Automatic restart

  • Quits and relaunches SOLIDWORKS every N files, to head off the memory it piles up over a long batch. 0 = never; it starts at 10.
  • Only instances SwMacroFlow started. If you pointed it at a SOLIDWORKS you already had open, restarting it would take your own work down with it, so it refuses.
  • Separately, it restarts SOLIDWORKS if it stops responding mid-batch and re-runs the files it never reached.

Run batches
in parallel

  • Several SOLIDWORKS instances pull from one queue: the next file goes to whichever is free, so one enormous assembly cannot strand the rest of the batch behind it.
  • Off by default. Instances do not share memory — a machine that cannot hold three copies of a big assembly finishes slower, not faster.
  • Only when SwMacroFlow starts SOLIDWORKS itself. Never for a run-once macro or a single file.

Instances

  • 2 to 4, and the row is greyed while the toggle above is off.
  • Read when you connect, not per run — change it and reconnect.
  • Two or three is usually all a workstation gains on large assemblies.
  • Each SOLIDWORKS takes 45–90 s to start, so the extras join a run already going.

💡 Tips

  • There is no Save button on this tab — every value here is written the moment you change it.
  • Turning parallel off does not forget the instance count. It is kept for when you turn it back on.
  • Leave automatic restart alone unless you have a reason: the default is there so a batch left running overnight survives it.
